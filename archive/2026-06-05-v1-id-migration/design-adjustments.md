## 调整详细说明

### 调整 1：`BaseEntity` JavaDoc 过时（Minor）

- **原始内容**：`BaseEntity` 顶部 JavaDoc 沿用 v1 文案 `"Identifiers are 32-char UUID hex strings (no dashes), generated by Hibernate's UUIDHexGenerator (alias 'uuid')."`
- **实际实现**：M01 将 id 类型改为 `Long` + `GenerationType.IDENTITY`，但 JavaDoc 文案未同步
- **修复**：JavaDoc 改为 `"Identifiers are Long (BIGINT AUTO_INCREMENT in MySQL), generated by JPA's GenerationType.IDENTITY"` + 标注迁移来源
- **触发**：Phase 5 Step 0 `code` 代理报 C 级（文档与代码不一致）
- **影响范围**：仅 JavaDoc 文本；不动行为；不影响测试

### 调整 2：`.stdd.yaml` requirements / scenarios 计数 7→8（Minor）

- **原始内容**：Phase 2 写 `.stdd.yaml` 时 `metrics.requirements: 7` / `metrics.scenarios: 7`
- **实际**：5 个 MODIFIED capability spec 实际共 8 个 Requirements / 8 个 Scenarios（backend-scaffold 2 + entity-organization 2 + entity-user 1 + entity-user-organization 2 + frontend-scaffold 1 = 8）
- **修复**：更新 `.stdd.yaml` 至 8 / 8
- **触发**：Phase 5 Step 0 `docs_skills` 代理报 M 级（metadata 数值不准）
- **影响范围**：仅 metadata；audit 数据更准

### 调整 3：v1-preserved bug — 编辑组织父节点保存不生效（Minor，Gate 3 手测命中）

- **原始内容**：v1（archive/2026-06-04-org-tree-and-employee）交付时，`OrganizationsPage.tsx` 编辑路径的 `onSubmit` 只调用 `updateOrganization()`（PUT `/organizations/{id}`），后端通用 update 端点显式不接受 `parentId`；改父节点必须走 PUT `/organizations/{id}/parent`（`moveOrganization()`）端点，但前端从未对接这条链路。
- **症状**：用户在编辑抽屉里把父节点改到另一棵分支，点保存，请求 200 但 `parent_id` 不变，刷新后回到原父。
- **触发**：Phase 5 Gate 3 手测路径 1（"编辑一个子节点 → 改父节点 → 保存 → 列表'全路径'列应变成新父链"）。
- **修复**：`OrganizationsPage.tsx` `onSubmit` 编辑路径里，update 之后比对 `req.parentId ?? null` 与 `editing.parentId`，不一致则调用 `moveOrganization(editing.id, nextParentId)`。后端 move 端点保留循环保护 + path/wholeName 重算 + 子节点级联。
- **影响范围**：仅 `OrganizationsPage.tsx`（3 行新增 import + 6 行 onSubmit 内逻辑）；不动 spec / design / 后端。回归：现有 11 前端测试 + 类型检查 + lint 全绿。
- **范围合规**：本文件在 design.md §10（frontend TS sweep）和 proposal Impact 范围内；修复 < 10 LOC；不引入新依赖；不动后端契约。故纳入本变更 delivery 而非另开 hotfix。

## 结论

3 项调整：调整 1-2 是文档级修正（评审命中）；调整 3 是 Gate 3 手测命中的 v1-preserved bug 顺手修复（10 LOC 内、文件在 Impact 内、不动 spec/design）。无任何设计层 / 行为层的偏离。Phase 4 build 完全按 Phase 2 spec 执行；migration 链路（BaseEntity → 3 entity → 3 service → 3 controller → 3 DTO → 3 frontend api → TreeSelect → tests）整体性 + 一致性符合 design.md。
